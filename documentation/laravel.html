    Integrasi

    Integrasi Laravel

    Memasang BLOK di Laravel 11/12 dengan struktur modular: setiap fitur membawa rute, view, migrasi, dan item menunya sendiri.

    • Gambaran & prasyarat
    • Instal Laravel & salin aset

    • Registrasi modul
    • Layout Blade

    • Contoh modul lengkap: Aset
    • Alternatif: nwidart/laravel-modules
    • Daftar periksa

    Gambaran & prasyarat

    BLOK adalah HTML/CSS/JS statis, jadi tidak ada paket Composer atau npm yang perlu dipasang. Integrasinya cukup tiga langkah: salin aset ke public/, pecah kerangka halaman menjadi layout Blade, lalu biarkan tiap fitur hidup sebagai modul yang mendaftarkan rute, view, migrasi, dan item menunya sendiri.

    • PHP 8.2+ dan Composer.
    • Laravel 11 atau 12 (struktur bootstrap/providers.php). Di Laravel 10, daftarkan provider di config/app.php.
    • Node/Vite tidak wajib; aset BLOK dimuat apa adanya.
    Konvensi di panduan ini

    Nama aplikasi blok-app, modul contoh Asset. Semua kelas CSS tetap .nb-* dan semua hook JS tetap data-*, sama seperti di template.

    1. Instal Laravel & salin aset

    Buat proyek baru, lalu salin CSS dan JS inti ke public/vendor/blok. Skrip demo tidak ikut disalin: data.js dan records.js berisi data fiktif, dan assets/js/pages/ berisi perilaku halaman demo.

    composer create-project laravel/laravel blok-app
cd blok-app

# salin dari folder repositori BLOK (sesuaikan path-nya)
BLOK=../blok-admin-ui-kit
mkdir -p public/vendor/blok/js
cp -R $BLOK/assets/css public/vendor/blok/css
cp $BLOK/assets/js/{icons,app,components,forms,tables,charts}.js public/vendor/blok/js/

    Setel bahasa ke Indonesia agar lang dan pesan validasi sesuai dengan teks UI:

    APP_NAME="BLOK"
APP_LOCALE=id
APP_FALLBACK_LOCALE=en

    Pesan validasi Bahasa Indonesia bisa ditulis di lang/id/validation.php (jalankan php artisan lang:publish lalu terjemahkan), atau gunakan paket terjemahan komunitas.

    3. Registrasi modul

    config/blok.php menentukan modul yang aktif dan urutan grup menu:

    <?php

return [
    // Nama folder di app/Modules. Urutan ini juga urutan pemuatan rute.
    'modules' => ['Dashboard', 'Asset'],

    // Urutan grup di sidebar. Item dengan grup di luar daftar ini tidak tampil.
    'groups' => ['Dashboard', 'Data', 'Operasional', 'Pengaturan'],
];

    Setiap modul menyumbang item menunya lewat module.php:

    <?php

return [
    'menu' => [
        [
            'key'    => 'assets',        // nilai data-page / data-nav
            'label'  => 'Aset',
            'group'  => 'Data',
            'icon'   => 'box',           // nama ikon di icons.js, tanpa awalan i-
            'route'  => 'assets.index',
            'active' => 'assets.*',      // pola request()->routeIs()
            'can'    => 'manage-assets', // opsional: ability Gate
        ],
    ],
];

    Satu service provider memuat semua modul: view dengan namespace (misalnya asset::index), migrasi, rute (dengan middleware web + auth), lalu menyusun menu untuk layout.

    <?php

namespace App\Providers;

use Illuminate\Support\Facades\Route;
use Illuminate\Support\Facades\View;
use Illuminate\Support\ServiceProvider;
use Illuminate\Support\Str;

class ModuleServiceProvider extends ServiceProvider
{
    /** Item menu dari semua modul, dikelompokkan per grup. */
    protected array $menu = [];

    public function boot(): void
    {
        foreach (config('blok.modules') as $name) {
            $path = app_path("Modules/{$name}");

            $this->loadViewsFrom("{$path}/Views", Str::kebab($name));
            $this->loadMigrationsFrom("{$path}/Database/Migrations");

            if (! $this->app->routesAreCached()) {
                Route::middleware(['web', 'auth'])->group("{$path}/routes.php");
            }

            foreach ((require "{$path}/module.php")['menu'] as $item) {
                $this->menu[$item['group']][] = $item;
            }
        }

        View::composer('layouts.blok.app', function ($view) {
            $user = auth()->user();
            $menu = [];
            $active = null;

            foreach (config('blok.groups') as $group) {
                $items = array_values(array_filter(
                    $this->menu[$group] ?? [],
                    fn ($item) => ! isset($item['can']) || $user?->can($item['can'])
                ));

                foreach ($items as $item) {
                    if (request()->routeIs($item['active'] ?? $item['route'])) {
                        $active = $item['key'];
                    }
                }

                if ($items) {
                    $menu[$group] = $items;
                }
            }

            $view->with(['blokMenu' => $menu, 'blokActive' => $active]);
        });
    }
}
    <?php

return [
    App\Providers\AppServiceProvider::class,
    App\Providers\ModuleServiceProvider::class,
];

    Hapus rute / bawaan di routes/web.php karena modul Dashboard yang akan memakainya. Ability seperti manage-assets didefinisikan dengan Gate::define() di AppServiceProvider.

    6. Komponen Blade

    Komponen anonim di resources/views/components/blok/ dipanggil sebagai <x-blok.nama>. Komponen field menghubungkan error validasi server ke pola aksesibilitas BLOK: aria-invalid, aria-describedby, dan .nb-error. Atribut data-error-id membuat forms.js memakai elemen error yang sama untuk validasi di sisi klien, sehingga pesannya tidak muncul dua kali.

    @props(['name', 'label', 'type' => 'text', 'value' => null, 'help' => null, 'required' => false])

@php
    $id = $attributes->get('id', 'f-'.$name);
    $errorId = $id.'-error';
    $helpId = $help ? $id.'-help' : null;
    $hasError = $errors->has($name);
    $describedBy = trim($helpId.' '.($hasError ? $errorId : ''));
@endphp

  <label class="nb-label" for="{{ $id }}">
    {{ $label }} @if ($required)<span class="nb-req" aria-hidden="true">*</span>@endif
  </label>
  <input {{ $attributes->except('id')->merge(['class' => 'nb-input']) }}

         @if ($type !== 'password') value="{{ old($name, $value) }}" @endif
         @required($required)
         @if ($describedBy) aria-describedby="{{ $describedBy }}" @endif
         @if ($hasError) aria-invalid="true" data-error-id="{{ $errorId }}" @endif>

  @endif
  @error($name)

    7. Form, validasi & flash

    forms.js selalu menahan submit agar validasi di sisi klien berjalan lebih dulu. Untuk form yang memang dikirim ke server, tambahkan data-server-submit. Partial berikut meneruskan form yang valid ke Laravel, menampilkan pesan flash sebagai toast, dan menangani konfirmasi hapus.

    <script>
  // Form valid (lolos forms.js) dengan data-server-submit dikirim sungguhan.
  document.addEventListener('nb:valid-submit', function (e) {
    if (e.detail.form.hasAttribute('data-server-submit')) e.detail.form.submit();
  });

  // <form data-confirm="Hapus aset ini?"> meminta konfirmasi sebelum dikirim.
  document.addEventListener('submit', function (e) {
    var message = e.target.getAttribute('data-confirm');
    if (message && !window.confirm(message)) e.preventDefault();
  });
</script>

@foreach (['success', 'warning', 'danger', 'info'] as $type)
  @if (session($type))
    <script>
      document.addEventListener('DOMContentLoaded', function () {
        NB.toast({ type: @json($type), message: @json(session($type)) });
      });
    </script>
  @endif
@endforeach

    Validasi di server tetap menjadi sumber kebenaran. Atribut HTML (required, type, minlength, pattern) hanya mempercepat umpan balik. Karena form.submit() tidak menyertakan nama tombol submit, bedakan aksi lewat rute atau input hidden, bukan lewat name tombol.

    <?php

namespace App\Modules\Asset\Http\Controllers;

use App\Http\Controllers\Controller;
use App\Modules\Asset\Http\Requests\AssetRequest;
use App\Modules\Asset\Models\Asset;
use Illuminate\Http\Request;

class AssetController extends Controller
{
    public function index(Request $request)
    {
        $assets = Asset::query()
            ->when($request->string('q')->trim()->value(), fn ($query, $q) => $query->where('name', 'like', "%{$q}%"))
            ->latest()
            ->paginate(15)
            ->withQueryString();

        return view('asset::index', compact('assets'));
    }

    public function create()
    {
        return view('asset::form', ['asset' => new Asset]);
    }

    public function store(AssetRequest $request)
    {
        Asset::create($request->validated());

        return redirect()->route('assets.index')->with('success', 'Aset berhasil ditambahkan.');
    }

    public function edit(Asset $asset)
    {
        return view('asset::form', compact('asset'));
    }

    public function update(AssetRequest $request, Asset $asset)
    {
        $asset->update($request->validated());

        return redirect()->route('assets.index')->with('success', 'Perubahan aset disimpan.');
    }

    public function destroy(Asset $asset)
    {
        $asset->delete();

        return back()->with('success', 'Aset dihapus.');
    }
}

    Views/form.blade.php memakai layout yang sama dan berisi form dari langkah 7. Setelah semua file ada, jalankan php artisan migrate. Menu Aset langsung muncul di grup Data.

    Alternatif: nwidart/laravel-modules

    Untuk proyek besar yang butuh generator (module:make, module:make-controller) dan modul yang bisa diaktifkan atau dinonaktifkan tanpa mengubah kode, struktur yang sama bisa dipindahkan ke paket nwidart/laravel-modules:

    composer require nwidart/laravel-modules
php artisan module:make Asset
    • Layout, partial, dan komponen x-blok.* tetap di resources/views aplikasi, dipakai bersama oleh semua modul.
    • View modul dipanggil dengan namespace huruf kecil, misalnya view('asset::index'), sama seperti panduan ini.
    • Item menu bisa tetap dibaca dari module.php. Ganti loop config('blok.modules') dengan daftar modul aktif dari paket (Module::allEnabled()).

    Daftar periksa

    • Aset di public/vendor/blok: hanya icons, app, components, forms, tables, charts. Jangan sertakan data.js, records.js, atau js/pages/*.
    • Setiap item menu punya key unik; nilai itu menjadi data-page dan data-nav.
    • Setiap view mengisi @section('title') yang unik.
    • Form yang dikirim ke server memakai @csrf, data-validate, dan data-server-submit, dan validasinya tetap ada di FormRequest.
    • Field memakai <x-blok.field> agar error server terhubung lewat aria-describedby.
    • Rute modul berada di bawah middleware auth. Item menu dengan can disembunyikan, dan aksesnya tetap dicek ulang di FormRequest atau policy.
    • Halaman 403, 404, dan 500 memakai layout standalone tanpa query database.
    • Jalankan php artisan route:cache dan view:cache saat deploy. Provider sudah melewati pendaftaran rute bila cache aktif.
